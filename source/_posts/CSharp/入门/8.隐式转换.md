什么是类型转换
类型转换就是不同变量类型之间的相互转换

隐式转换的基本规则 ——> 不同类型之间自动转换
大范围装小范围


### 知识点一 相同大类型之间的转换
``` CSharp
// 1. 有符号   long ——> int ——> short ——> sbyte

long l = 1;
int i = 1;
short s = 1;
sbyte sb = 1;
// 隐式转换：int 隐式转换成了 long
// 可以用大范围装小范围的类型（隐式转换）
  l = i;
// 不能够用小范围的类型去装大范围的类型
// i = l;

// 2. 无符号   ulong ——> uint ——> ushort ——> byte

// 3. 浮点数   decimal     double ——> float

// decimal这个类型没有办法用隐式转换的形式去存储double和float
// float是可以隐式转换成double

// 4. 特殊类型   bool  char  string
// 他们之间不存在隐式转换
```


### 知识点二 不同大类型之间的转换

#### 1.无符号和有符号之间

有符号的变量是不能够隐式转换成无符号的
有符号变量是可以装无符号变量的，前提是范围一定要是涵盖的，存在隐式转换
因为有符号的变量可能会超过这个无符号变量的范围
因为有符号的变量不管是多少都在无符号变量的范围内

#### 2.浮点数和整数（有、无符号）之间

浮点数是可以装载任何类型的  整数的
decimal不能隐式存储float和double
但是它可以隐式的存储整形
double -> float -> 所有整形（无符号、有符号）
decimal -> 所有整形（无符号、有符号）

整数装浮点数  整数是不能隐式存储  浮点数  因为  整数  不能存小数

#### 3.特殊类型和其它类型之间

bool 没有办法和其它类型  相互隐式转换

char 没有办法隐式的存储其它类型的变量

char类型可以隐式的转换成整形和浮点型
char隐式转换成数值类型是
对应的数字其实是一个ASCII码

计算机里面存储2进制
字符 中文 英文 标点符号 在计算机中都是一个数字
一个字符对应一个数字 ASCII码就是一种对应关系

string 类型无法和其它类型进行隐式转换


### 总结隐式转换规则
// 高精度（大范围）装低精度（小范围）
double ——> float ——> 整数（无符号、有符号） ——> char
decimal ——> 整数（无符号、有符号） ——> char
string 和 bool 不参与隐式转换规则的


视频补充内容：
char 之所以能够隐式转换为整形和浮点数，是因为 char 类型是一个16位无符号整数，用于表示 Unicode 字符的编码值。
取值范围是 0 到 65535，所以它可以隐式转换为比它宽度更大的数值类型 long、ushort、ulong 等都可以。

### Deepseek(AI) 知识概念补充:

核心问题：为什么需要它们？
在计算机早期，各个国家/公司制定了不同的编码标准来用数字表示字符（比如 ASCII 用 65 表示大写字母 A）。但问题是：

1.冲突：数字 200 在一种编码里可能是 È，在另一种编码里可能就是 Ш，打开文件就会乱码。
2.容量不足：像 ASCII 只有 128 个字符，根本无法表示中文、日文、阿拉伯文等成千上万的字符。

为了解决全球文字的混乱问题，Unicode 应运而生。

---
一、Unicode（统一码、万国码）
你可以把 Unicode 想象成一部 “全球字符大字典”。

  目标：为这个世界上每一个字符分配一个唯一的、统一的编号，无论属于哪种语言、平台或程序。

  这个编号叫做“码点”。码点通常用十六进制表示，并前缀 U+。

  例如：字母 A 的码点是 U+0041，汉字“中”的码点是 U+4E2D，笑脸符号 😊 的码点是 U+1F60A。

  它只定义编号，不关心如何在计算机中存储。它解决了“这个字符对应哪个数字？”的问题。

小结：Unicode 是一个标准，它定义了一个庞大的字符集和每个字符对应的唯一码点。

---
二、UTF-8（8位 Unicode 转换格式）
现在我们知道每个字符在 Unicode 字典里有个编号（码点），但如何把这个编号存储到计算机的字节流里呢？这就是 “编码” 要做的事情。

UTF-8 就是 最流行的一种 Unicode 编码实现方式。

  目标：将 Unicode 码点转换成一串字节，以便在计算机中存储或通过网络传输。

  特点：它是一种变长编码。这意味着不同的字符可能占用 1 到 4 个不等的字节。


UTF-8 的编码规则（非常巧妙）：
1.对于单字节字符（ASCII 字符）：码点范围 U+0000 到 U+007F。UTF-8 只用一个字节表示，并且字节的格式与 ASCII 编
码完全一样。

  好处：所有 ASCII 文本本身就是有效的 UTF-8 文本！这意味着对纯英文环境是100%兼容的，非常节省空间。

2.对于多字节字符（如中文、表情符号）：使用 2、3 或 4 个字节表示。

  每个多字节序列的第一个字节有特殊的前缀（如 110, 1110, 11110）来表明这个字符总共占用了几个字节。

  后续的字节都以 10 开头。

举例：汉字“汉”的编码过程
1.查字典（Unicode）：首先，我们查到“汉”字的 Unicode 码点是 U+6C49。

2.编码（UTF-8）：

  码点 U+6C49 落在 U+0800 到 U+FFFF 的范围内，UTF-8 规则规定它需要用 3个字节 来编码。

  通过一套固定的算法，将 6C49 这个码点的二进制位填充到 3 个字节的模板中。

  最终得到三个字节：11100110 10110001 10001001（这是二进制），转换成十六进制就是 0xE6 0xB1 0x89。

3.存储/传输：计算机或网络传输的就是 E6 B1 89 这三个字节。

解码：当程序读取到这三个字节时，看到第一个字节以 1110 开头，就知道这是一个3字节的字符，于是读取接下来的两个字节，通过反向计算，还原出码点 U+6C49，最终在屏幕上显示“汉”字。


一个完美的比喻：

Unicode 就像 “世界语” 的概念，它规定“苹果”这个概念在所有语言中都叫 apple（码点）。

UTF-8 就像用 “莫尔斯电码” 来实际发送和接收“apple”这个词。它决定了如何将 a-p-p-l-e 这一串字母转换成 .- .--. .--. .-.. . 这样的信号（字节序列）。

---
为什么 UTF-8 如此流行？
  1.完美兼容 ASCII：处理纯英文文本时，文件大小和性能与 ASCII 时代无异。

  2.空间高效：对于以英文为主的网页和软件，UTF-8 比使用固定2字节或4字节的编码（如 UTF-16）更节省空间。

  3.无字节序问题：UTF-8 的字节序列没有“大端序”和“小端序”的困扰，简化了数据处理和传输。

  4.是 Web 的标准：超过 98% 的网页使用 UTF-8 编码。

因此，在现代软件开发中，强烈建议始终使用 UTF-8 编码，这可以一劳永逸地解决几乎所有字符乱码问题。
