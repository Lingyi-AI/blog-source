### 一、多个脚本文件的核心原则（C#/.NET）
在 C# 项目中，一个 .cs 文件通常对应一个类，这是最规范的组织方式，便于维护和复用。


### 二、文件拆分与命名规范
1.类与文件同名：一个 .cs 文件只包含一个类，文件名必须与类名完全一致（包括大小写）
例：Player.cs 中只定义 public class Player { ... }
例：Monster.cs 中只定义 public class Monster { ... }
2.命名空间一致：同模块的类放在同一个命名空间下，便于管理和引用。

``` CSharp
// Player.cs
namespace MyGame.Entities
{
    public class Player { }
}

// Monster.cs
namespace MyGame.Entities
{
    public class Monster { }
}
```


### 三、类之间的调用与访问
1.引用其他类：在同一个命名空间下，可直接实例化其他类；不同命名空间需用 using 引入。

``` CSharp
// Game.cs
using MyGame.Entities;

public class Game
{
    public void Start()
    {
        Player player = new Player();
        Monster monster = new Monster();
    }
}
```

2.访问修饰符：
public：类 / 成员可被任何其他类访问。
internal：仅在当前程序集（项目）内访问（默认权限）。
private：仅在当前类内部访问。
protected：当前类和子类可访问。


### 四、项目结构示例（游戏项目）
MyGame/
├─ Entities/
│  ├─ Player.cs      // 玩家类
│  └─ Monster.cs     // 怪物类
├─ Systems/
│  ├─ CombatSystem.cs // 战斗系统
│  └─ UISystem.cs     // UI系统
└─ Game.cs            // 主入口类


### 五、必备知识点总结
1.单一职责：一个类只做一件事，一个文件只放一个类。
2.命名规范：文件名 = 类名，PascalCase 大驼峰命名。
3.命名空间：按功能 / 模块划分，避免类名冲突。
4.访问控制：合理使用 public/internal/private，保证封装性。
5.依赖管理：通过 using 引入依赖，避免循环引用。


### 六、如何优化多文件项目
按功能拆分：将不同功能模块拆分为独立文件，如 “实体类”“系统类”“工具类”。
避免循环依赖：A 类依赖 B，B 类又依赖 A，会导致编译错误。
** partial 类 **：超大类可拆分为多个 partial 文件（不推荐滥用，仅用于代码生成场景）。
单元测试：每个类对应独立的测试文件，便于验证功能。
